# 1部屋の3D脱出ゲーム — Codexへの引き継ぎ仕様

承認日：2026年10月3日（日本時間）\
状態：ユーザー承認済みの企画を実装するための仕様\
対象：初期版・PCブラウザー・日本語・1部屋／1ステージ

## 1. 実装担当Codexへの依頼

本書に従い、起動から脱出まで遊べるブラウザーゲームを制作してください。企画の相談は完了し、制作に引き継ぐ内容が承認されています。技術的な細部は本書の体験と範囲を保って判断してください。

Game Studioを用い、Three.js向けの制作手順、必要なアセット制作、ブラウザーでのプレイテストまで進めてください。実装だけで完了とせず、3つの謎を解いて脱出できることを確認してください。

本書の具体的な暗号、配置、数値は承認済みの企画を実装可能にするための初期設定です。実装上の調整は可能ですが、手掛かり・答え・ヒントを必ず整合させてください。ステージ追加、自由なカメラ回転、戦闘などの範囲拡張は行いません。

## 2. ゲームの概要

- ジャンル：複数のギミックを解き、鍵を入手して部屋から脱出するゲーム。
- 舞台：中世ファンタジー風の古い宿屋の一室。
- 雰囲気：温かい照明、少し不思議な空気、昔ながらの日本製RPGらしい冒険感。
- 想定プレイ時間：初見で10〜15分程度。
- 主要ギミック：3つ。順番に解くと出口の鍵を入手できる。
- 時間制限、ゲームオーバー、誤入力によるペナルティは設けない。
- 既存作品のキャラクター、紋章、画面、音楽を複製せず、独自のデザインにする。

基本ループ：部屋を観察 → 小道具を調査 → 手掛かりを読む → 仕掛けを操作 → アイテム入手 → 次の仕掛け → 鍵で扉を開ける → 脱出成功。

## 3. 技術構成

- Node.js：開発環境、依存関係管理、開発サーバー、ビルドに使用。
- Three.js：ブラウザー内の3D描画。
- 推奨構成：TypeScript + Vite + Three.js。Reactは必須にしない。
- 初期版は静的配信可能とし、アカウントやバックエンドは不要。
- 部屋、家具、扉、キャラクターは3D形状で構成。単純な形状から開始してよいが、完成時は世界観を統一する。
- 外部モデルを採用する場合の形式はGLB／glTFを基本とする。
- ゲーム進行と所持品は描画オブジェクトから独立した状態として管理する。
- メニュー、調査画面、所持品、ヒント、音量設定はHTML／CSSの重ね合わせで構成する。
- 移動は決められた経路と調査地点で成立させる。物理エンジンは必要になった場合のみ導入する。

## 4. 画面全体の表示とカメラ

### ブラウザー表示

- ブラウザーのコンテンツ領域全体をゲームに使う。ページの余白やスクロールをなくす。
- ウィンドウのサイズ変更に合わせて描画、カメラ、UIを更新する。
- 通常表示でも画面いっぱいに遊べる。「全画面」ボタンでブラウザーのタブ等を隠す表示を切り替えられるようにする。
- 全画面切り替えはユーザー操作から実行し、非対応時も通常表示で遊べる。Escで解除しても進行を保持する。
- まず1280×720および1920×1080で、手掛かりと操作ボタンを読めることを確認する。

### プレイ中の視点

- 斜め上から見下ろす固定方向のカメラ。プレイヤーによる回転操作なし。
- 手前の壁や天井を省くなど、必要な小道具とキャラクターを確認できる構図にする。
- ホイールと「＋／−」ボタンで部屋を拡大・縮小できる。
- 初期目安は全体表示を1倍、最大2倍。部屋全体を見る倍率より小さくしない。
- 小道具を選ぶと、その位置を中心に拡大できるようにする。カメラの向きは変えない。
- 「全体表示」でズームと注視位置を初期状態へ戻す。
- 調査画面や設定画面の上では、ホイールが部屋のズームを誤作動させない。
- 文字や暗号を読む調査画面はズーム倍率に依存しない大きさで表示する。

## 5. スタート画面と開始演出

- 室内から閉ざされた木製扉に向き合う構図。
- 手前中央に、扉の前に立つ操作キャラクターの後ろ姿を配置する。
- キャラクターは小さなマントと旅装を身に着けた独自の冒険者。
- 左右に家具と灯りが見え、これから部屋を探索する期待感を出す。
- 暫定タイトルは「古い宿屋からの脱出」。タイトルと「ゲーム開始」を表示する。
- 保存データがある場合は「続きから」と「最初から」を表示する。「最初から」は確認後に進行を初期化する。
- 開始ボタンを押すと、カメラがゆっくり引き上がり、部屋全体を見るプレイ視点へ移る。演出は2〜3秒程度を目安とする。
- このカメラ移動は開始時の演出。プレイ中の自由な回転や視点操作は追加しない。
- 演出中は小道具の操作を受け付けず、終了後に探索を開始する。

## 6. 部屋とキャラクターの動作

### 必要な配置

- 奥側中央：鍵の掛かった木製の出口扉。
- 左側：ベッド、机、数字錠付きの引き出し。
- 右側：本棚、紋章付きの宝箱。
- 奥の壁：数字の手掛かりとなる絵、宝箱の手掛かりとなる旗。
- 灯りや敷物など：視認性を損なわない範囲で配置。
- 机の上：数字錠の入力順を示すメモ。

すべての進行に必要な対象を、回転なしで見つけられる位置に置く。小さな対象には十分なクリック判定を設ける。背景と操作対象を光やカーソル変化などで区別する。

### 移動と調査

- 小道具をクリックすると、キャラクターがその手前の調査地点まで歩き、到着後に説明や謎解き画面を開く。
- 家具を突き抜けないよう、障害物を避ける決められた経路を用意する。すべての調査地点に到達可能とする。
- 自由な歩行操作、ジャンプ、戦闘は設けない。
- キャラクターの向きは歩行方向や調査対象に合わせて変えてよい。カメラ回転とは区別する。
- 待機と歩行が分かる簡潔なアニメーションを付ける。
- 調査への移動は長くなりすぎないようにし、長距離でもおおむね2秒以内を目安とする。
- 移動中の新しいクリックは最後に選んだ対象へ切り替える。到着前の調査や古い対象の画面表示を起こさない。
- 調査画面が開いている間は、背後の小道具のクリックを無効にする。
- 壁の絵や旗も近くの閲覧地点へ移動してから拡大表示する。

## 7. 謎解きの詳細

### ギミック1：机の引き出しの数字錠

- 壁の絵に「太陽2個・月4個・星3個」を描く。
- 机のメモに、入力順を示す「太陽 → 月 → 星」を記す。
- プレイヤーは絵の各記号を数え、3桁の数字錠へ入力する。
- 初期設定の正解は「243」。
- 正解すると引き出しが開き、本棚の配置を示す紙片を入手する。
- 紙片には「葉 → 波 → 炎」の記号を順に描く。
- 絵の数は背景装飾と混同しない。記号と数字は生成画像の文字精度に依存させず、必要に応じてコードで描画して正確さを保証する。

ヒント：
1. 壁の絵と机のメモを見比べてみよう。
2. メモの順に、絵の太陽・月・星の数を入力しよう。
3. 太陽は2個、月は4個、星は3個。答えは243。

### ギミック2：本棚の仕掛け

- 押せる本を5冊用意し、背表紙に「葉・波・炎・山・雪」の異なる記号を付ける。
- 紙片の入手後、「葉 → 波 → 炎」の順に3冊を押すと仕掛けが開く。
- 正解すると隠し収納から、宝箱にはめる紋章を入手する。
- 紙片の入手前も本棚を調べられるが、仕掛けの入力は紙片入手後に有効化する。
- 間違った順序は入力をリセットし、何度でもやり直せる。
- 色だけで識別させず、記号と短いラベルを併用する。

ヒント：
1. 引き出しから手に入れた紙片が、本棚の手掛かりになりそう。
2. 紙片の記号と同じ背表紙を探して、左からの順に押そう。
3. 葉の本、波の本、炎の本の順に押そう。

### ギミック3：紋章付きの宝箱

- 紋章を選び、宝箱をクリックして使用すると、4つの紋章ボタンが操作可能になる。
- 宝箱のボタンは「太陽・月・星・王冠」。
- 壁の旗には、上から「月 → 王冠 → 太陽 → 星」の順で記号を並べる。
- 旗の上から下へ読むことが分かる矢印または飾りを添える。
- 初期設定の正解は「月 → 王冠 → 太陽 → 星」。
- 間違った入力はリセットし、再挑戦できる。
- 正解すると宝箱が開き、出口の鍵を入手する。

ヒント：
1. 宝箱には紋章をはめる場所がある。壁の旗も調べてみよう。
2. 紋章をはめたら、旗を上から読んで同じ順にボタンを押そう。
3. 月、王冠、太陽、星の順に押そう。

### 脱出

- 出口の鍵を選び、扉をクリックして使用すると解錠する。
- 解錠後の扉に「開ける」を表示。クリックで扉が開き、キャラクターが外へ歩く。
- 脱出成功の演出と結果画面を表示する。
- 結果画面には「脱出成功！」と「もう一度遊ぶ」を表示する。
- 鍵がない場合も扉を調べられ、鍵が必要であることを説明する。

## 8. 所持品、調査、ヒントのUI

- 所持品は画面下に小さく表示。アイコンと名前を付ける。
- アイテムはクリックで選択し、選択状態を明示。再クリックまたはキャンセルで解除できる。
- 使用対象をクリックすると移動し、到着後に使用判定する。
- 使えない対象には短い説明を返し、アイテムを失わない。
- 紙片は所持品から何度でも読める。
- 紋章と鍵は正しい対象へ使用した際に消費し、使用済み状態を保存する。
- メモ、絵、旗は何度でも再確認できる。
- 調査画面には見出し、必要な拡大図、短い説明、操作、閉じるボタンを配置する。
- ヒントは各ギミックに3段階。プレイヤーの操作で1段階ずつ開く。最終段階を開く前に答えを表示する旨を伝える。
- 未解決の次のギミックを案内し、依存する未入手アイテムが必要な場合はその取得を促す。
- 設定や長い説明は必要な時だけ開き、部屋を大きな常設パネルで囲まない。

## 9. BGMと効果音

- BGMは「謎を解くワクワク感」「発見への期待」「心地よい不思議さ」を目標とする。
- 軽いピチカート、木管、柔らかなベル系の音を中心に、中程度のテンポと控えめな旋律にする。
- 恐怖演出や強い緊張感を主調にしない。考える時の邪魔にならない音量にする。
- 1〜2分程度を目安に、継ぎ目の目立たないループ曲を用意する。
- 音は開始／続きからなどのユーザー操作を起点に再生する。自動再生制限による失敗を処理し、再生できなくてもゲームを進められる。
- BGMと効果音それぞれに音量調整とミュートを用意する。
- 本を押す、正解、アイテム入手、解錠、脱出成功などに短い効果音を付ける。
- スタート画面への戻りや再開でBGMが多重再生されないようにする。
- 謎の正解や操作結果は、音声に加えて画面でも伝える。
- 音源はオリジナル制作、または使用条件を確認できる素材とする。素材名・出典・ライセンス・必要なクレジットを記録する。
- 初期版で外部音源が確保できない場合は、Web Audio等で上記の雰囲気に沿うオリジナルのループを制作し、無音のままで完成としない。

## 10. 画像・アセット制作

- Game StudioのThree.js制作手順を基本に進める。
- ImageGen：壁の絵の装飾、木や石のテクスチャ、旗、雰囲気づくりなどの画像制作に使用する。
- Generate 2D Sprite：所持品アイコンや小さな演出素材の制作に使用する想定。
- 実行環境に「Generate 2D Sprite」という名称のスキルがない場合は、利用可能なGame Studioのsprite-pipelineやImageGenを用途に応じて使う。使用できない機能を使用済みと記載しない。
- 操作キャラクターは3Dで表現する。2D画像だけを置いて3Dキャラクターの代替にしない。
- 絵や旗の謎に必要な記号数・順序、文字、当たり判定は実装側で保証する。
- 生成画像の中に焼き込まれた不正確な文字を手掛かりに使わない。
- 外部素材は出典と利用条件を記録する。仮素材で始めても、最終成果物では見た目を統一し、不足を明記する。

## 11. 保存と再開

- 同じブラウザー・同じ配信元で、続きから遊べる自動保存を行う。
- ギミックの解決、アイテムの取得／使用、ヒント開示、脱出状態を保存する。
- 音量とミュート設定も保存する。
- 移動途中や開いた調査画面は保存しなくてよい。再開時は安全な待機位置と通常のプレイ画面から始める。
- 再開しても、使用済み紋章が宝箱から外れる、鍵を再取得できるなどの状態不整合を起こさない。
- 保存データにバージョンを付け、不正または旧形式のデータで起動不能にならないようにする。
- 保存できない環境では、その場でのプレイを継続できるようにする。
- 「最初から」「もう一度遊ぶ」は確認後にゲーム進行を初期化する。音量設定は保持する。

## 12. 初期版の範囲外

- 2部屋目以降、複数ステージ。
- 戦闘、敵AI、会話分岐、複雑なストーリー。
- 一人称の自由移動、自由なカメラ回転。
- マルチプレイ、アカウント、サーバー保存。
- モバイル向け操作の最適化。

## 13. 実装の進め方

1. 全体表示、固定カメラ、部屋、小道具、クリック移動を作る。
2. 3つのギミック、所持品、鍵と扉、脱出までの進行を実装する。
3. スタート画面、後ろ姿のキャラクター、カメラの開始演出を実装する。
4. ズーム、調査画面、段階的ヒント、自動保存を整える。
5. 生成画像等でアセットを仕上げ、BGMと効果音を実装する。
6. ブラウザーで通しプレイと表示確認を行い、問題を修正する。

## 14. 完成判定と検証

### 見た目と操作

- [ ] ブラウザーの表示領域全体にゲームが表示され、ページのスクロールがない。
- [ ] スタート画面で、部屋と扉、扉に向き合うキャラクターの後ろ姿が見える。
- [ ] 開始演出後、斜め上の固定視点で探索できる。
- [ ] 回転なしで、すべての必要な小道具を発見し調査できる。
- [ ] ホイール、＋／−、全体表示が動き、拡大後も操作対象を選べる。
- [ ] キャラクターが家具を突き抜けず、小道具の手前へ歩いてから調査する。
- [ ] 移動中の連続クリックで、古い対象の調査画面が開かない。
- [ ] 1280×720、1920×1080、ウィンドウのサイズ変更でUIが切れず読める。
- [ ] 全画面への切り替え／解除で進行や操作を失わない。

### ゲーム進行

- [ ] 手掛かりを見て「243」を入力し、紙片を入手できる。
- [ ] 葉・波・炎の順に本を押し、紋章を入手できる。
- [ ] 紋章を使い、月・王冠・太陽・星の順に押し、鍵を入手できる。
- [ ] 鍵を扉に使い、扉を開け、脱出成功画面まで到達できる。
- [ ] 誤入力や誤ったアイテム使用後も、正しい手順で進められる。
- [ ] 同じアイテムの重複取得や、意図しない順序での進行が起きない。
- [ ] 3段階のヒントが、それぞれの実装済みの答えと一致する。
- [ ] 紙片等を再確認でき、読んだ後も所持品が失われない。
- [ ] ギミックの途中と解決後に再読み込みして、正しい状態から続けられる。
- [ ] 脱出後の再読み込みと、最初からやり直す操作が成立する。

### 音と安定性

- [ ] 開始操作後にBGMが鳴り、ループの継ぎ目が不自然でない。
- [ ] BGMと効果音の音量・ミュートを別々に設定できる。
- [ ] やり直しや再開でBGMが重複しない。
- [ ] ミュート状態でも手掛かりを読んで脱出できる。
- [ ] 通常のプレイ中に進行を妨げるエラーがない。
- [ ] WebGLが使えない、またはアセット読み込みに失敗した場合に、白紙のままではなく状況と再試行方法を表示する。

主な進行分岐、誤入力、アイテム使用、保存復元には必要な自動検証を加える。見た目、歩行、クリック、音はブラウザーの実際のプレイで確認する。少なくともChromium系ブラウザーで通しプレイを行い、他のブラウザーを未確認の場合はその範囲を報告する。プレイ時間10〜15分は目標であり、未測定なら実測済みと扱わない。

## 15. 制作完了時の引き渡し

- ゲームのソースコードと利用アセット。
- 開発起動、ビルド、ローカルでの確認方法を記載したREADME。
- 採用した実行環境・依存関係のバージョンとロックファイル。
- 画像・音源の出典、生成素材の記録、ライセンス／クレジット一覧。
- 確認したブラウザーと表示サイズ、通しプレイ結果、残っている制約。

外部公開や有料素材の購入は本書の制作範囲に含めない。まずローカルで遊べる完成物を引き渡す。
